# Stripe Projects

> Provision and manage services from the CLI. Stripe Projects lets you or your agents provision hosting, databases, auth, AI, analytics, and more, generate and store credentials, and manage usage and billing — one command per service, no dashboards.

**Website:** https://projects.dev  
**Documentation:** https://docs.stripe.com/projects  
**Developer resources:** https://projects.dev/developers/  
**Provider catalog:** https://projects.dev/providers/

---

## What is Stripe Projects?

Stripe Projects is a plugin for the Stripe CLI that provisions third-party services on your behalf and hands back real credentials. It replaces the manual loop of signing up for a service, creating an account, generating API keys, copying them between dashboards, and clicking through configuration pages.

It does not generate an application or write code for you. You keep whatever stack you already have; Stripe Projects supplies the infrastructure underneath it. Services are created in provider accounts that you own, so you can leave at any time and keep everything.

Because every operation is a single command with structured output, it works the same whether a person or an agent is driving it.

## Getting Started

Stripe Projects is a plugin for the Stripe CLI. This installs the CLI, the plugin, and the agent skill in one command:

```bash
npm install -g @stripe/cli@latest && stripe plugin install projects && npx skills add https://github.com/stripe/ai --skill stripe-projects -y -g
```

To install just the CLI and plugin, drop the last step. On macOS, Homebrew works too:

```bash
brew install stripe/stripe-cli/stripe && stripe plugin install projects
```

For Windows, Linux, and Docker, see https://docs.stripe.com/stripe-cli/install

Free to use. You pay providers directly at their standard rates.

Create a project and sign in:

```bash
stripe projects init
```

Find a service to provision:

```bash
stripe projects catalog
stripe projects search <keyword>
```

Provision a service. Services are addressed as `<provider>/<service>`:

```bash
stripe projects add neon/postgres
```

Pull the generated credentials into your local `.env`:

```bash
stripe projects env --pull
```

## Features

### Programmatic
One workflow to provision services, manage credentials, and change plans, instead of a different tool and a different dashboard for every provider. Every command accepts `--json` and `--no-interactive`, so agents can run the same flows a person does.

### Secure credentials
Credentials are generated by the provider and returned to you directly, then synced to your local `.env` and an encrypted vault. No copying keys between browser tabs. Rotate any service's credentials with a single command.

### Portable
Environment variables stay portable across machines, teammates, and agents. Project state lives in `.projects/`, so a collaborator can run `stripe projects pull <projectID>` and get the same stack.

### Billing in one place
Set up billing once and share it across your stack. Upgrade or downgrade tiers, monitor usage, and manage subscriptions from the CLI, with spend limits you control.

### No vendor lock-in
Services are provisioned in provider accounts you own. If you stop using Stripe Projects, the accounts and resources remain yours.

## CLI Reference

Install: `npm install -g @stripe/cli@latest && stripe plugin install projects`
Agent skill: `npx skills add https://github.com/stripe/ai --skill stripe-projects -y -g`

### Project lifecycle

| Command | Description |
|---------|-------------|
| `stripe projects init [name]` | Create a project and sign in or register |
| `stripe projects status` | View project name, services, tiers, and health |
| `stripe projects list` | View all projects on your Stripe account |
| `stripe projects pull <projectID>` | Set up an existing project in a new local directory |

### Discovery

| Command | Description |
|---------|-------------|
| `stripe projects catalog` | List all available providers and services |
| `stripe projects catalog <provider>` | Show services for a specific provider |
| `stripe projects catalog <category>` | Show providers in a category |
| `stripe projects search <keyword>` | Find provider services by keyword |

### Provisioning

| Command | Description |
|---------|-------------|
| `stripe projects add <provider>/<service>` | Provision a service |
| `stripe projects remove <provider>/<service>` | Deprovision and remove a service |
| `stripe projects services list` | List all services in a project |
| `stripe projects link <provider>` | Connect a provider to your project |
| `stripe projects unlink <provider>` | Disconnect a provider from your project |
| `stripe projects open <provider>` | Open a provider's dashboard in the browser |

### Credentials

| Command | Description |
|---------|-------------|
| `stripe projects env` | View credentials (values hidden by default) |
| `stripe projects env --pull` | Update local `.env` and replenish the credentials vault |
| `stripe projects rotate <provider>/<service>` | Generate new credentials for a service |

### Tiers and billing

| Command | Description |
|---------|-------------|
| `stripe projects upgrade <provider>/<service>` | Upgrade a service tier |
| `stripe projects downgrade <provider>/<service>` | Downgrade to a lower tier or free plan |
| `stripe projects update <provider>/<service>` | Modify a resource within the same provider |
| `stripe projects billing add` | Add or replace a payment method |
| `stripe projects billing show` | Display the payment method on file |
| `stripe projects billing update` | Modify payment method or adjust spend limit |

### Sharing and context

| Command | Description |
|---------|-------------|
| `stripe projects share` | Generate a shareable URL encoding your service stack |
| `stripe projects import <URL>` | Add services from a shared stack |
| `stripe projects switch-account` | Change active Stripe account |
| `stripe projects llm-context` | Generate a combined LLM context file |

### Flags useful to agents

| Flag | Purpose |
|---|---|
| `--json` | Output as structured JSON |
| `--no-interactive` | Disable prompts; fail if input is required |
| `--auto-confirm` | Accept confirmation dialogs automatically |
| `--accept-tos` | Accept provider terms without prompting |
| `--quiet` | Suppress non-essential output |
| `--debug` | Enable Stripe API request logging |

This reference mirrors https://projects.dev/llms.txt, which is the authoritative source.
